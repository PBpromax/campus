# 用户版界面与回复

2026-10-27，按用户反馈调整鸿蒙客户端。范围是现有四业务主客户端及助手输出，不改变原业务分类、权限、确认、幂等和审计规则；M3部署工作仍暂停。

## 使用方式

- 首页选择跑腿、学习、借用或其他互助，也可以直接描述目标。
- “对话”显示用户消息和助手答案，输入区固定在底部。学习小问题直接交流，不要求先填写任务资料。
- 助手整理的需求单独成卡，点击“保存到需求”才会应用；“我的需求”可展开修改，完整表单作为手动入口保留。
- 核对需求后进入“发布求助”，明确标题、报酬、地点、完成时间。日期与时间可通过原生选择器点选。
- 最后一步核对实际约定及操作影响，再点“确认发布”。接单、取消也有独立确认，信用后果不隐藏。
- “任务”分为找互助、我的互助、发布求助；“消息”联系已参与任务的另一方；“我的”查看历史对话和助手使用次数。

主要页面采用统一的浅色背景、深绿主色、白色卡片和明确字号层级。会话/草稿版本、SSE、Schema、模型函数名、回执UUID及语言引擎比对不放进日常页面。内部标识继续用于鉴权、版本校验和排障。历史操作显示的是**操作时状态**，不把历史回执当作当前任务状态。

## 助手输出

1. 继续关闭供应商思考模式，忽略`reasoning_content`字段；后端在流式输出和持久化前过滤明确的`think/analysis/reasoning`标签，包含跨片段标签。保留数学关系、用户需要的教学推导。
2. 学习和未分类澄清仍可流式显示自然语言答案，提示要求简短、只问必要信息，不复述内部字段、函数或执行规则。未标记的模型文字仍可能不理想，不能声称任意文本都能被完美识别。
3. 对已选定的跑腿/借用/其他业务，模型的过程性原文不直接透出。先校验结构化建议，再由业务评估生成简短结果摘要，例如“需求整理好了，请核对下方内容，合适的话再保存”。卡片承担详细信息展示。
4. 校验不会代替用户保存：建议绑定最新会话版本，只有用户采用才写草稿；发布/接单/取消另行确认。无效建议不成为已执行结果。
5. 新提示版本`campus-needs-v3-user`。任务结果摘要在校验完成后输出，不能把模型网关首段原文耗时当成用户看到摘要的时延。模型路由、出域检查和预算保持不变。

前端也过滤历史回复中明确的思考标签；不会批量改写或删除旧消息。模型建议仍可能提取错误，需用户核对，不把更简洁的界面等同于语义零错误。

## 实际验证

- 后端完整289项通过（当前工作区含此前M3第四步2项健康测试，本轮新增6项），设备端36项通过（原33＋展示规则3项），主HAP和测试HAP构建安装成功。
- 真实学习小问题直接获得解释，无思考标签、函数名或字段清单。
- 首次任务回复仍有“先存草稿”和重复追问，保留原始记录；随后加入校验结果摘要，使用新的需求再次验证。后一次不是改写前一次模型回复。
- 新版页面完成真实建议采用、保存、日期/时间选择、独立确认、发布测试任务21、第二账号接单、发送消息及发布者读取，最后确认取消。测试账号的信用只按本次前后差验证-5。
- 四业务入口、任务/消息/个人页面实际截图复核；本轮真实模型调用3次（学习1、任务摘要修正前后各1），没有自动重试或真实支付。

截图不是完整真机、无障碍读屏或所有20情境的真人评估。现阶段仍为本机模拟器中的用户界面版本，发布签名、云端接入及真人试用未完成。
