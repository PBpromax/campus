## 2. 已实现的模型

共同结构：会话、类别候选、当前类别、独立业务草稿、情境列表、对话消息、待补充项、冲突、字段来源、会话版本、草稿版本和确认版本。`AUTO`只在设计入口表达“未选择”，不会成为生产类别。

| 业务 | 字段数 | 本步保存与校验的重点 |
| --- | --- | --- |
| RUNNING | 14 | 代办类型、物品数量、取送位置、时间、当面/放置、通知、完成确认、搬运限制、代买预算 |
| STUDY | 8 | 问题上下文、知识点、卡住步骤、讲解起点、优先问题、可用时间、沟通方式、语言 |
| BORROW | 16 | 用途、规格、数量、借用与归还时间、取还交接、送达条件、说明、配件、使用限制 |
| OTHER | 11 | 协助类型与目标、资源、时间地点、渠道、完成标准、授权条件、人数与组织意向 |

共49个字段、20种可叠加情境。定义在`backend/src/main/resources/domain/need-fields.json`，由新版M1字段清单整理而来。M2将“设计输入/模拟拆分”措辞改为“用户称已获同意（待核实）/希望拆分”等意向表达。所有填入字段仅标记`USER_DECLARED`，空值为`UNKNOWN`；既不是库存事实，也不是工具执行授权。真实资源与对方同意后续由服务端可信来源确认。

ArkTS的`NeedCategory`、`NeedSession`、`NeedDraft`等承载网络契约。字段以白名单键和字符串值传输，数字/时间在服务端检查；这一步尚未把模型输出变成可执行代码，也不接受任意字段。

数据库新增`need_sessions`、`need_drafts`、`need_messages`三个表。一会话每类别最多一份草稿；消息按所属业务保留，统一入口原话单独保存。不改原`demands`发布字段或任务状态机。

## 3. 状态与不变量

- 规则只给分类候选，不擅自切换业务；混合目标等待用户明确选一项，未知目标保持待澄清。
- 切换业务保留各自草稿；新类别从空字段开始。恢复旧业务时清除其旧确认，不从其他类别复制物品或地点等字段。
- 信息不完整或有冲突时可以保存草稿，但不能确认。数量需1—99整数；预算需正数；时间必须是有效的具体日期时间；借期、取送窗口顺序要一致。当前时间不含时区，跨时区与更完善的自然语言时间解析待后续实现。
- 跑腿区分当面与放置交付，放置需明确位置及照片/通知约定，静默情境与电话通知冲突时提示。借用检查规格未知、使用区间与归还限制；多人OTHER明确组织意向，不据此创建多人订单。
- 普通学习只要求当前问题上下文，基础薄弱/时间紧/远程/语言情境再增加对应澄清。消息保存并不等于AI已经回答，尚未接入真实模型。
- 内容修改、消息补充、重新表达目标及切换恢复都使旧确认失效。确认只绑定当前草稿版本，重复确认同一版本不产生副作用。**草稿确认不是发布授权。**
- 所有写操作携带会话`revision`。事务锁定本人的会话后核对版本，过期写入返回409，不覆盖新内容；客户端保留输入，并提供明确放弃本地输入后重新加载的入口。
- JWT决定会话所有者，客户端不能指定ownerId；读取、修改、删除别人的会话均返回404。确认只核对草稿，不建立原平台任务。

## 4. 新接口

统一路径`/api/need-sessions`，均需要登录JWT。成功仍使用原平台`{code,message,data}`响应结构。

| 方法与后缀 | 作用 / 正文 |
| --- | --- |
| GET `/catalog` | 四类字段定义 |
| POST 空后缀 | 新建本人会话，无请求正文 |
| GET 空后缀 / GET `/{id}` | 本人会话列表 / 恢复指定会话 |
| PUT `/{id}/category` | `{revision,category}`，用户选择或恢复业务 |
| PUT `/{id}/draft` | `{revision,fields,contexts}`，字段部分更新、情境完整替换 |
| POST `/{id}/intake` | `{revision,text}`，保留原目标并返回规则分类候选 |
| POST `/{id}/messages` | `{revision,text}`，保存当前类别的问题上下文 |
| POST `/{id}/confirm` | `{revision}`，仅核对当前草稿 |
| DELETE `/{id}` | `{revision}`，删除本人的测试/需求会话 |

400表示格式、类别或字段白名单错误；404表示会话不存在或不属于本人；409表示版本过期或仍需选择业务；422表示缺失信息、约束冲突或消息达到单会话200条上限。未登录沿用安全框架的403。新错误处理仅作用于这些接口，避免改变原接口的历史HTTP行为。
