## 技术债与数据缺口

1. BORROW没有独立物品/借期/归还资源模型；STUDY没有知识缺口和发布前上下文。原型新增字段仅在内存验证，M2才迁移。
2. 前端报酬允许0，后端@Positive要求>0；无偿小问题不能被自动映射成0元发布。
3. expectedTime只有一个时间点，不能替代借用起止、最晚拿到和归还；需要以后明确生产数据语义。
4. 接单未见锁或版本控制；先查再更新存在并发争抢风险。评价去重同样需并发验证。
5. 用户更新/删除控制器未核对操作者和路径ID；申诉列表/公开需求详情的敏感字段访问边界需检查。消息发送验证发送者参与，但接收者是否为对方仍有缺口。
6. 管理申诉不是通用人工客服队列；已有任务聊天不是AI发布前会话。
7. ddl-auto=update、无分页需求列表、原前端依赖审计和大包提示列为后续技术债，不在M1全面重构。
8. 已处理的迁移问题：云端默认配置、生产JWT默认值、演示账号默认创建、UTF-16 SQL和原用户导出；变更见接管记录。

## 样本性质与统一记录方式

下面十例均为AI辅助设计、待验证假设，不是真实访谈。示例日期、地点、物品和题目用于原型，不表示资源真实存在。原话以外的预填约定均标为设计样本数据。

借用共同目标：借到适用物品并明确使用与归还约定。学习共同目标：获得适合当前知识缺口与情境的帮助。


## B01 规格不确定（BORROW）

| 项目 | 设计样本 |
| --- | --- |
| 用户原话 | 明天展示要借一个转接器，我不知道接口怎么选。 |
| 目标 | 借到能连接电脑与投影的转接器 |
| 约束 | 设备接口和视频输出能力未知 |
| 缺失信息 | 规格、兼容条件、需要本人核实的信息 |
| 必要追问 | 电脑接口是什么？投影接口是什么？不知道时能提供型号吗？ |
| 交互变化 | 规格确认；未知能力标为待核实，不给出可用库存或适配保证 |
| 允许操作 | 修改规格、补充型号、确认请求草稿 |
| 成功条件 | 明确可核实规格；不把“想借”当“肯定有” |
| 验证状态 | 待真实试用；原型规则与浏览器行为验证另列 |
