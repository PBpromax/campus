# 04 个人上下文、信息责任与授权

## 1. 三类上下文

| 类别 | 例子 | 设计规则 | 原型实现 |
| --- | --- | --- | --- |
| 长期声明偏好 | 用户明确要求以后默认中文或异步交流 | 单独问是否保存；可查看、修改、撤回 | 不保存长期记忆，不将本次选择当作长期偏好 |
| 推测偏好/能力 | 根据几次问题推测“基础薄弱” | 标为候选；不得固化成标签或默认权限 | 不生成画像；无法确认的信息保持未知 |
| 临时上下文 | 今晚21点后接收、脚受伤、某一题两步没懂 | 仅支持本任务；结束/过期后清除或按规则匿名化 | 仅内存 session，刷新/重置清空；无 localStorage、sessionStorage 和外部请求 |

当前“静默”“中英双语”“从基础开始”都只对本次任务生效。未来要成为长期偏好必须另行获得用户同意；M1 没有真实记忆服务。

## 2. 信息状态与责任

| 状态 | 原型例子 | 如何处理 |
| --- | --- | --- |
| 用户直接表达 | “两个快递”“中英双语” | 有限规则识别、标明来自本次消息，允许纠正 |
| 用户明确填写/选择 | 用户选放置交付、填写交接点 | 标为用户填写；尚不等于授权执行 |
| 未知 | “某个地点”“第二步到第三步”但无表达式 | 显示待补充，不能编造地点或题目 |
| 推测候选 | “今晚”可能代表多个时间窗口 | 不替用户选一个时点，继续澄清 |
| 授权的约定版本 | 用户确认 v9 的交接卡 | 只模拟执行该版本；修改产生新版本并使旧确认失效 |

原型暂不表达语言模型置信度。字段的 explicit 指来源于直接表达或填写，不表示自动解析永远正确，用户仍需检查。

## 3. 字段生命周期与展示

| 信息 | 用途 | 应展示给谁 / 保留边界 |
| --- | --- | --- |
| 校区、粗粒度取件点 | 明确任务范围 | 未来公开需求可按权限展示；本次只在浏览器内 |
| 精确交接点、临时存放点 | 交接安排 | 未来仅向获授权协作者展示，不放入公开推荐理由 |
| 本次接收能力限制 | 判断可行的交接方式 | 只表达必要限制；不形成身体状况画像 |
| 时间与静默通知 | 调整流程和通知约定 | 仅本次；未真正发送通知 |
| 题目、表达式、卡住步骤 | 延续学习问题上下文 | 本会话可见，不自动推断成绩/人格 |
| 模拟事件 | 展示纠正、确认、撤销等行为 | 仅类型、版本、字段名、动作名；不记录消息或精确位置 |
| 测试截图 | 证明演示流程实际运行 | 只使用演示数据，无真实用户隐私；仓库内可查看 |

原型整页刷新清空上下文；浏览器自身的输入恢复/系统截图属于浏览器或操作系统行为，不是原型记忆功能。

## 4. 授权与控制点

- 继续聊天是表达信息；修改字段是更新候选约定；确认按钮是对当前版本的模拟授权。
- 已确认后修改时间、地点、方式或任何约定字段，旧确认失效，须重新确认。
- 普通学习小问题不要求发布授权；用户主动切换发布/预约时才显示确认卡。
- 未确认、字段缺失、约束冲突、已撤销/解决/接管时，不能模拟执行副作用。
- “模拟人工接管”仅显示摘要，并明确队列未接入；固定表单可在规则识别失败时继续填写。

## 5. 与未来业务状态的衔接

M2 中授权、订单、工具执行与审计应由服务端保存和验证；精确位置与任务状态不能只存在聊天上下文。生产系统应将用户身份、授权范围、有效期、确认参数和幂等键纳入工具校验。这里是设计要求，不是本阶段已部署能力。
