# 07 用户试用提纲与空白反馈表

状态：**尚未开展真实用户试用。**本文件是执行材料，不是研究结果。自动化测试与浏览器操作不代替用户理解、满意度或完成效率。

## 1. 试用目标

验证不同情境是否真的改变追问和交互：快递交接约定能否表达清楚；学习小问题能否自然延续，不被表单打断。优先观察行为，再问感受。

## 2. 参与与说明

建议邀请有实际校园取件或学习求助经验的同学，匿名编号记录。人数由实际可招募情况决定，课件未给 M1 统一人数；不要为凑数量虚构。

开始时说明：原型仅使用有限规则和演示数据，不调用真实 AI，不发布任务、不联系真实协作者。请用演示位置与题目，避免输入真实手机号、取件码等信息。询问是否同意记录匿名操作观察，截图另行征得同意。

## 3. 操作任务

| 任务 | 观察重点 |
| --- | --- |
| 快递：先当面，再改为放置 | 是否理解位置需重新明确，是否注意到确认失效 |
| 快递：上课静默、截止早于交接 | 是否理解冲突，是否能自主调整或填写暂存方案 |
| 快递：不知道校区或取件点 | 追问是否清楚，固定表单是否容易找到 |
| 学习：只问第二步到第三步 | 是否顺利补表达式，继续追问是否保留上下文 |
| 学习：时间紧或基础薄弱 | 追问是否必要，是否有被问太多的感觉 |
| 学习：从短消息转为预约 | 是否理解何时出现确认卡，时段要求是否合理 |

不要先教用户每个按钮在哪里；只在阻塞时介入，并记录介入点。不能对数学内容是否讲懂作模型能力评价，因为原型没有真实答疑。

## 4. 访谈问题

1. 你能用自己的话说出这次任务会做什么、不会做什么吗？
2. 哪个追问必要，哪个追问多余或令人困惑？
3. 改交接方式后重新填地点，是否符合你的实际习惯？
4. 放置交付更需要照片、文字位置还是其他方式？为什么？
5. 学习小问题是否可以照自己的口语表达？哪里显得过于正式？
6. 何时需要找同学协助，何时只想继续问一个小问题？
7. 你是否理解这只是模拟，以及“确认”“撤销”“接管”的含义？

## 6. 待验证假设

H1：交接方式分支比统一描述字段更容易明确约定。

H2：时间冲突解释能够促使用户主动选择替代，而不是误以为系统会自行解决。

H3：小知识点求助只追问当前上下文，比强制完整表单更自然。

H4：发布/预约时才出现确认卡，用户仍能理解操作边界。

H5：规则识别来源标签、模拟提示和回退入口能够减少“系统已理解/执行”的误解。

以上均无真实用户结论。试用后保存支持与反对证据，必要时修改本体、追问顺序和卡片。
