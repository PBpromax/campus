# 02 个性化需求样本与分析

## 分析方法与来源

来源为课件第7页的 M1 要求、当前项目源码和本对话中用户确定的范围。下列十个样本均为 **AI 辅助构造的待验证设计假设**；不属于真人访谈，不据此报告用户比例或偏好频率。

每个业务固定一个共同目标，变化的是当次情境、约束和交互。硬约束只能由用户修改；软偏好可提出替代建议，但不能擅自放宽。未知信息保持未知；样本中的具体地点/时段仅用于演示。

## A. 快递跑腿

共同目标：**完成一批快递的取件与约定交接**。发布方与跑腿方角色不变，不加入历史合作者偏好。

### E01 行动不便

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 我脚受伤不能下楼，仙林校区有三个快递在北门驿站，希望今晚送到宿舍楼门口。 |
| 目标 | 获得自己能够接收的交付，减少搬运与移动 |
| 硬约束 | 本次不能下楼；三个快递必须纳入清单 |
| 偏好 | 尽量简化交接，尚未声明长期偏好 |
| 已知 / 缺失 | 校区、取件点、件数已表达；具体楼号、交接方式、明确时间、联络/完成确认待补充 |
| 必要追问 | 楼门口是否确实可接收？哪栋楼的哪个位置？当面还是放置？什么时间？是否有搬运限制？ |
| 交互变化 | 显示本次接收限制；把交接点和件数放入确认卡，允许调整位置 |
| 允许操作 | 修改约定、比较交接方式、确认模拟任务、撤销或模拟接管 |
| 成功条件 | 交接约定与接收能力一致；必要字段齐备；身体情况仅作本次上下文 |

### E02 上课中

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 仙林校区北门驿站有一个快递，我上课到21点，21点以后才能当面交付，上课期间请静默通知。 |
| 目标 | 完成取件，同时不打断上课 |
| 硬约束 | 21点前不能当面交接；上课期间静默通知 |
| 偏好 | 下课后尽快交接；具体窗口仍需确认 |
| 已知 / 缺失 | 校区、取件点、件数、当面、静默已知；交接点、联络方式和最晚取件时间待确认 |
| 必要追问 | 21点后的具体窗口和交接点是什么？驿站几点截止？若截止早于下课，是否接受提前取件并约定暂存？ |
| 交互变化 | 时间窗口、静默通知卡；截止与交接时间冲突时显示风险和替代选择 |
| 允许操作 | 用户调整时段，或明确选择提前取件及暂存点；未解决冲突不可确认 |
| 成功条件 | 不自动放宽时间限制；临时存放方案由用户选择，不假定有人保管 |

### E03 新生认路

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 我是新生，想取一个快递，不知道北门是哪一个校区，也不知道在哪里交接。 |
| 目标 | 先明确位置，再完成取件交接 |
| 硬约束 | 校区与地点尚未知，不能猜测并发布 |
| 偏好 | 使用能识别的地标与清晰说明 |
| 已知 / 缺失 | 件数已知；校区、完整取件点、交接地点、方式、时间待确认 |
| 必要追问 | 快递短信写的是哪个校区、哪个驿站？你能确认的公共地标在哪里？ |
| 交互变化 | 地点字段优先澄清，可输入地标；确认卡逐项标出未知信息 |
| 允许操作 | 补地点、修正校区、固定表单回退、模拟人工接管 |
| 成功条件 | 含糊的“北门”不被自动改成仙林校区；用户能识别双方约定位置 |

### E04 跨语言沟通

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 我在仙林校区，北门驿站有一个快递，需要中英双语确认，今晚当面交付。 |
| 目标 | 双方对取件、时间、交接有一致理解 |
| 硬约束 | 不因语言变化改变业务地点、件数和交接方式 |
| 偏好 | 本次中英双语标签和关键约定说明 |
| 已知 / 缺失 | 校区、取件点、件数、当面、语言已知；具体交接点/时间/通知/联络待确认 |
| 必要追问 | 具体交接点和时间是什么？是否按“当面 / In person”交付？ |
| 交互变化 | 双语交接标签与确认标题，结构化业务字段仍保持同一来源 |
| 允许操作 | 更换语言、纠正字段、确认模拟任务 |
| 成功条件 | 双语标签未修改业务事实；完整自动翻译能力尚未验证 |

### E05 个性化交接方式

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 仙林校区北门驿站有两个快递，今晚放在某个地点就行，放好通知我。 |
| 目标 | 按用户指定方式完成交接 |
| 硬约束 | 放置地点必须明确；完成不能只由系统猜测 |
| 偏好 | 无需见面，但可以随时改成当面交付 |
| 已知 / 缺失 | 校区、取件点、件数与放置意图已知；“某个地点”和“今晚”仍不够具体，通知/完成确认待明确 |
| 必要追问 | 放在什么具体位置？什么时间？普通还是静默通知？需要位置说明还是放置照片，再由你确认？ |
| 交互变化 | 方式比较卡；放置展示地点和凭证，当面展示联络方式；切换方式后重新确定位置 |
| 允许操作 | 比较/切换方式、填写地点、选择通知/完成确认、重新确认 |
| 成功条件 | 含糊位置阻止模拟执行；变更方式后旧确认失效；两种方式有不同必要字段 |

## B. 学习求助

共同目标：**获得适合当前问题的帮助，理解课程知识或卡住的步骤**。TUTORING 在本次表示求助与协作，不自动扩展为长期辅导或完整课程学习档案。

### L01 基础薄弱

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 高数求助，我基础薄弱，导数和极限的关系不太明白，不知道该从哪里开始。 |
| 目标 | 找到能够继续理解的讲解起点 |
| 硬约束 | 讲解应与当前理解水平相适应，不默认已有所有前置知识 |
| 偏好 | 从必要基础或一个具体例子开始；由用户选择 |
| 已知 / 缺失 | 课程、疑惑范围已知；缺哪一部分、讲解深度待澄清 |
| 必要追问 | 你对“变化率”或“极限”哪一部分有印象？从必要基础开始还是先看一个例子？ |
| 交互变化 | 一次一个定位问题和讲解深度选项，不索取完整成绩/学习档案 |
| 允许操作 | 补上下文、选择起点、继续消息、标记已解决；需要协作者时再模拟发布 |
| 成功条件 | 用户可修正起点；问题范围逐步明确；不把本次“基础薄弱”固化为标签 |

### L02 时间紧张

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 我今晚只有20分钟复习高数，时间很紧，链式法则一直没明白。 |
| 目标 | 有限时间内优先理解一个关键问题 |
| 硬约束 | 本次只有20分钟，不默认延长或安排长期课程 |
| 偏好 | 简短、聚焦，不一次覆盖全部章节 |
| 已知 / 缺失 | 知识点与时长已知；优先解决定义、识别还是应用待选择 |
| 必要追问 | 这20分钟先解决哪个问题？例如怎样识别复合函数，或为什么要乘内层导数？ |
| 交互变化 | 优先问题与时长摘要；在对话中缩小范围，而非强制预约 |
| 允许操作 | 调整优先级、继续短消息、标记已解决、按需预约 |
| 成功条件 | 时长不被当成预约时段；聚焦由用户决定；范围可修改 |

### L03 时间或地点受限

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 我想请同学讲高数里的链式法则，只能在线异步交流，今晚没有整块时间。 |
| 目标 | 在零散时间完成问题交流 |
| 硬约束 | 在线异步，不能默认线下或实时会面 |
| 偏好 | 根据双方节奏短消息回复 |
| 已知 / 缺失 | 主题与异步方式已知；如需发布，可补充期望回复节奏 |
| 必要追问 | 希望什么时候前得到回复？若没有硬截止，可以继续留言；不必强设预约时间 |
| 交互变化 | 保留问题上下文，继续消息；选择实时预约时才出现时段字段 |
| 允许操作 | 异步交流、模拟发布、用户主动切换预约 |
| 成功条件 | 普通异步交流不强制完整时间段；主动预约时增加必要确认 |

### L04 跨语言解释

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 我在学高数，想问链式法则，希望用中英双语解释相关术语。 |
| 目标 | 正确理解同一个知识点的术语与步骤 |
| 硬约束 | 两种语言中的问题范围一致，不编造题目 |
| 偏好 | 中英术语对照；讲解深度按当前理解选择 |
| 已知 / 缺失 | 主题和语言已知；具体卡住的点可继续补充 |
| 必要追问 | 卡在 chain rule / 链式法则的定义、识别，还是计算中的一步？ |
| 交互变化 | 双语沟通提示与同一问题摘要；允许用户继续描述 |
| 允许操作 | 修改语言、补表达式、连续追问、按需发布 |
| 成功条件 | 不将跨语言等同于基础薄弱；不重写用户提供的表达式；不声称真实模型已答疑 |

### L05 碎片化小问题

| 项目 | 分析 |
| --- | --- |
| 用户原话 | 第二步到第三步怎么来的？我只卡在这一小步。 |
| 目标 | 弄懂当前一个知识点或步骤，理解后结束 |
| 硬约束 | 没有表达式就不能猜题；只补必要上下文 |
| 偏好 | 不规范也可表达，短消息补充与连续追问 |
| 已知 / 缺失 | 卡在第二步到第三步；两步表达式未知 |
| 必要追问 | 把这两步贴出来就好；之后可以继续说“这里为什么取负号？” |
| 交互变化 | 对话为主、无需标题/预算/校区/预约表单；保留上下文，用户可标记解决 |
| 允许操作 | 补表达式、继续追问、纠正问题、标记解决；有协作需求时再发布/预约 |
| 成功条件 | 新消息不清空已有表达式；不强制完整流程；问题解决由用户反馈 |

## 组合与纠正场景

特殊情境可叠加，不对应五种永久用户类型。例如“新生＋静默通知＋放置交付”使用同一个任务的三种约束组合，不另建固定人格页面。

组合演示应覆盖：E02 时间冲突＋E05 改交接方式；L02 时间紧张＋L05 只问一步；E04 双语＋用户手动纠正地点。测试现有约束是否延续，避免每条消息重置任务。

## 待验证假设

用户是否更喜欢一次一个问题？是否需要照片还是文字确认？小知识点问答是否需要问题摘要？跨语言标签是否足够清晰？这些均需要实际试用后判断，不能由样本数量推导。
