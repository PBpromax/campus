# 01 接管现状、稳定底座与升级边界

## 1. 基线与代码来源

旧代码来自 Octonauts 的 P4-yrh（`664f7f437c4a579fc153b1e5198208e6a90d35cf`）。新仓库 <https://github.com/PBpromax/campus> 的 main 从清理后的独立快照开始，初始提交 `92bc9067ef4b795e9407d091ef21c8c8f78cee83`。旧 P0—P4 作业文件未上传；旧历史保留在本地归档分支。

这份盘点依据当前源码，不将旧 README 的计划功能视为实现证据。

## 2. 稳定业务底座

| 能力 | 源码位置（仓库相对路径） | 当前判断 |
| --- | --- | --- |
| 注册、登录、JWT | backend/src/main/java/com/campushub/auth/ 与 security/ | 存在实现；JWT 密钥已改为环境变量，未验证完整数据库登录链路 |
| 个人资料 | backend/.../profile/；frontend/src/views/ProfileView.vue | 存在查询/修改，不包含长期 AI 记忆 |
| 需求发布/浏览/详情 | backend/.../requirement/；frontend/src/views/PublishRequirementView.vue | 统一参数 title、description、budget、type；分类白名单 |
| 接单、订单列表/详情 | backend/.../order/ | 自接单拦截、事务与需求唯一订单约束；完成/取消接口缺失 |
| 评价与信用 | backend/.../evaluation/ | 已完成订单参与者可评价，规则加减分；原有单元测试另见实际报告 |
| 消息通知 | backend/.../notification/ | 查询/已读与创建方法存在，未发现业务调用创建方法 |
| 管理下架 | backend/.../admin/ | 角色校验存在，关联订单协调尚缺 |

原系统全部分类保留。M1 仅使用 EXPRESS（快递跑腿）与 TUTORING（学习求助）；STUDY_HELP（学业辅导）不合并、不迁移。当前需求大厅分类与发布分类不一致，属于原有缺陷。

## 3. 从统一表单到动态体验

| 原交互 | M1 演化设计 |
| --- | --- |
| 所有分类填写标题、预算、描述 | 先表达目标；按当前情境补充必要字段 |
| 交接细节藏在 description | 明确取件点、件数、交接方式、地点、时间和完成确认 |
| 学习小问题也进入统一发布表单 | 可直接贴一句问题，补表达式、继续短消息；只有发布/预约才确认 |
| 页面显示信息，但不主动识别缺口 | 规则原型提示缺失与冲突；无法识别时允许人工填写 |
| 用户修改与执行边界不清晰 | 每个约定版本独立确认；修改后旧确认失效 |

## 4. 技术债与数据缺口

| 缺口 | 影响 | 本次处理 |
| --- | --- | --- |
| 订单状态枚举与真实迁移不完整 | 无法证明完整发布→完成→评价链路 | 列为后续底座任务；M1 不伪造真实完成 |
| 根 SQL 与后端内置 SQL 字段/表不一致 | 环境启动和升级存在不确定性 | 记录缺口；原型独立运行 |
| Vue 存在重复 JS/TS 入口和配置 | 维护边界不清楚 | 原型采用独立工程，避免误改原平台 |
| 通知未与业务事件接通 | “静默通知”不能真实执行 | 原型只保存通知约定并展示模拟 |
| 缺少结构化交接/学习上下文 | AI 难以检查和纠正需求 | M1 用前端领域结构验证字段与交互；未迁移业务数据库 |
| 缺少 AI 授权/幂等/审计契约 | 模型不能安全产生业务副作用 | M1 建立设计规则；M2 接后端落实 |
| 缺少特殊情境用户反馈 | 无法确认设计是否适合真实用户 | 交付试用提纲与空白表，不编造满意度 |

## 5. 本次改动与兼容性

- 后端 `campushub.jwt.secret` 使用 `JWT_SECRET_BASE64`，配置必须由本地安全环境提供；更换密钥使旧 Token 失效。原型不需要该环境变量。
- 原有业务 API、数据库、分类与 Vue 页面未因 M1 原型改变。
- 新增独立 Vue 规则原型、机器可读本体、测试、构建包和设计文档。
- 所有匹配、发布、预约、通知和人工接管均是模拟。没有服务方候选数据，原型的“方案比较”是交接/沟通方式比较，不能称为真实人员匹配。
