# ADR-001：M3模型部署与路由（初版）

日期：2026-10-24。状态：沿用现有云API形成可运行基线；容量、预算、数据最小化和故障恢复验证未完成，评审前补充。

## 问题与选择

本项目需要四业务的需求澄清、学习小问题解释、受限字段建议与操作意图建议。M2已接通DeepSeek云API，ArkTS客户端只访问Java后端，模型密钥留在后端。当前选择继续使用这条路径，以本机后端部署作为开发验证环境；云API部署方式不等于本项目后端已上云。

| 方案 | 依据与代价 | 本阶段决定 |
| --- | --- | --- |
| 云API | M2有真实四业务联调；仍依赖外部网络，需核对用量、费用和发送数据 | 作为当前单一路由 |
| 校内/私有模型 | 需提供机器、模型许可、推理服务与运维证据；本项目尚无这类环境 | 不声称已实现；若后续有资源再做对照 |
| 端云混合 | 端上已有规则和固定表单；复杂生成在云端。端上规则不是端上LLM | 当前采用规则回退；不冒称部署了本地模型 |

该选择基于已运行能力，不断言该模型优于所有替代品。模型效果比较应使用统一评测集和真实错误样本，留待M4及后续实验。

## 当前路由及版本

- 供应商：DeepSeek；默认配置模型`deepseek-flash`，实际调用记录使用运行配置中的模型名。
- 业务入口：四业务共用单一路由；最多20条当前类别相关历史消息与当前类别草稿，附字段目录。
- Prompt版本：`campus-needs-v1`。后续改变提示词、上下文筛选或工具契约应更新版本并保留比较依据；供应商模型别名可能升级，当前不能保证权重快照可复现。
- `propose_draft`和`suggest_action`只是候选；规则校验、用户采用和独立工具确认继续生效。
- 单实例最多4个并发（`MODEL_MAX_CONCURRENT`允许1—4），同用户最多1个。满载立即429，未配置503。无自动重试、隐式排队或多供应商切换。
- 模型不可用时保留输入，使用完整表单与真实任务双方聊天。没有后台偷偷换供应商。

## 数据边界

现在发送的是系统规则、字段目录、当前类别草稿和相关消息；不主动读取用户表的密码、JWT、信用记录或任务伙伴聊天，Key只用于HTTP鉴权。不向模型发送数据库连接配置或其他用户会话。

当前消息/字段自由文本仍可能包含用户手动输入的手机号、取件码或其他敏感细节，尚无自动脱敏与出域确认机制。M3第三步需形成字段级允许/拒绝策略并验证，不能宣称“已保证所有发送内容无敏感信息”。需要真实机密的业务操作应由受控工具完成，不能靠提示词放开模型权限。

新增观测仅记录随机关联编号、路由模板、模型/Prompt版本、时间、结果枚举和Token统计；不写入提示词、回答、建议参数、Authorization或Key。编号仅用于诊断，不能用作鉴权或幂等键。数据库原有业务审计的用户/任务信息继续按本人权限返回。

## 用量、成本与预算

根据[DeepSeek Chat Completions官方协议](https://api-docs.deepseek.com/api/create-chat-completion/)，请求明确启用`stream_options.include_usage`，解析流内最终用量。中断、失败、无用量或异常统计标记未知，不能记作“0元”。缓存命中/未命中字段若缺失则为未知，不能凭空推算命中率。

待配置真实单价后，单次估算为：

`(cacheHitTokens × 命中输入单价 + cacheMissTokens × 未命中输入单价 + completionTokens × 输出单价) / 1,000,000`

单价、计价币种和生效日期需要从实际供应商账号核对；没有缓存拆分时使用保守上界或标记无法精确估算，不能假设所有输入都命中。估算应与供应商账单对账，不把运行内存计数当账单。

本轮不设虚假的已生效日预算：账号/日配额、峰值预算、价格配置、费用计量持久化和跨实例计数尚未实现。当前只限制单次输出1600 Token及并发，不等于已限制每日花费。负载测试优先使用本地可控模型替身；真实API仅在明确小样本预算下复核。

## 后续验收清单

1. 对响应头后停顿的流验证真正的全程截止时间。现有HTTP请求timeout与SSE超时不能据此直接证明后台读取一定及时退出。
2. 对并发满载、取消和断流检查槽位释放；部署多实例前更换单进程限流。
3. 明确账号配额、预算和熔断策略；禁止有真实副作用的工具自动重试。
4. 按业务字段检查出域与最小上下文，不复制全库作为RAG。当前规则本体并非已部署向量检索。
5. 记录模型调用、候选采用与工具结果各自的失败率，不能用模型SUCCEEDED代表任务发布成功。
